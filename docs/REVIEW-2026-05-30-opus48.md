# Spiel — Senior Review (Claude Opus 4.8, 2026-05-30)

Review of the DeepSeek v4 Pro build of **Spiel**, a local-first macOS voice-to-text app.
Reviewed at commit `8d57346` on `main`. This document is the basis for the from-scratch
rebuild on a separate branch. **The DeepSeek build is preserved on `main`.**

---

## 1. Executive Verdict

**Overall: 4 / 10. Not production-ready. Not daily-driver ready.**

The Rust backend is clean, modular, and compiles warning-free. The problem is not
architecture — it is that **the core product loop is not wired together and key features
are faked**:

- Audio capture is real.
- **Default transcription is a hardcoded mock string.** Real local transcription requires
  the user to hand-configure a `whisper.cpp` binary + model path that is never bundled,
  downloaded, or guided.
- **"Insert at cursor" is not implemented** — it copies to the clipboard and tells the user
  to press Cmd+V. The tagline ("puts it where your cursor is") is unfulfilled.
- **Clipboard save/restore is fake** — the saved clipboard is computed then discarded.
- **The entire guided workflow and the entire OpenAI integration are compiled but
  unreachable from the UI.**
- **No macOS microphone usage string or entitlements** — a packaged/hardened build is
  killed by TCC on first mic access.
- **Privacy docs directly contradict the code** (claim "never makes network calls / never
  calls OpenAI / never stores API keys" while shipping an OpenAI HTTP client + in-memory
  key store).

**Biggest 3 risks:** (1) headline feature is fake by default; (2) privacy docs are false;
(3) no macOS permission config → recording dies in a real bundle.

**Continue the architecture?** Yes — refactor/wire-up, not rebuild, *would* have been the
call. The user has chosen a clean from-scratch rebuild to remove the dead scaffolding and
implement the loop honestly.

## 4. Critical Findings

### F1 — Default transcription is a hardcoded mock (Critical)
`transcription.rs:165` returns a fixed `"This is a mock transcript…"`. `settings.rs:38`
defaults `default_transcription_engine: "mock"`. A fresh install transcribes nothing real.

### F2 — "Insert at cursor" is clipboard-only (Critical)
`commands.rs:230-297`, `clipboard.rs:9` ("Paste simulation … is NOT implemented"). Spiel
never inserts text; it writes the clipboard and asks the user to paste.

### F3 — No macOS microphone usage string / entitlements (Critical)
No `Info.plist`/`*.entitlements`; `tauri.conf.json` has no `bundle.macOS` section. A hardened
build is terminated by TCC on first mic access.

### F4 — Clipboard "save/restore" is fake (High)
`clipboard.rs:55` `save_and_replace` returns a `SavedClipboard` that `commands.rs:266`
discards. `restore_clipboard` (`commands.rs:302`) just re-reads the current clipboard.

### F5 — Privacy/security docs contradict the code (High)
`docs/security.md:21-27` and `README.md:39` claim no network calls / no OpenAI / no key
storage. Reality: `transcription_openai.rs`, `cleanup_openai.rs` POST to `api.openai.com`;
`secrets.rs` stores keys in memory; CSP whitelists `api.openai.com`.

### F6 — Workflow + OpenAI UI entirely unwired (High)
`lib.rs:234-249` registers ~17 workflow/OpenAI commands; `src/lib/api.ts` stops at Phase 9
and never calls them. UI shows OpenAI only as disabled "planned" options.

### F7 — Temp WAV files never deleted (High)
`audio.rs:242` writes to `temp_dir`; no `remove_file` anywhere. `clear_last_recording`
explicitly keeps the file. Raw voice recordings accumulate in `/tmp` indefinitely.

### F8 — Audio assumes f32 and is unbounded (Medium)
`audio.rs:179-187` builds a `&[f32]` stream regardless of device `SampleFormat`; the sample
buffer has no cap. Non-f32 devices fail; long sessions grow memory without limit.

### F9 — Settings engine validation mismatch (Low)
`settings.rs:198` validates against `["mock","local_whisper","cloud"]` but `commands.rs:947`
routes on `"openai"`. `"cloud"` is accepted but routes nowhere; `"openai"` is rejected.

### Doc/marketing drift
README says Phase 11, code says Phase 12; "44 commands" vs 50 registered; self-contradictory
roadmap; `capability_statuses` reports transcription/cloud as "implemented".

## 5. Privacy Verdict

> **I would not trust this build as documented for private dictation** — not because it
> exfiltrates data (cloud is off by default and currently unreachable) but because the
> privacy documentation is materially false about the code that is present, and it leaves
> raw audio in `/tmp` forever. The defaults are good; the honesty and disk hygiene are not.

## 7. What the Rebuild Must Get Right

1. **Real local transcription out of the box** — embedded Whisper (`whisper-rs`) with a
   first-run model fetch (checksummed, disclosed), not a manual CLI binary path. Local is the
   default; there is no "mock" engine in the product path.
2. **Real insertion at the cursor** — clipboard write + synthesized paste (CGEvent Cmd+V)
   behind an Accessibility-permission flow, with clipboard-only fallback. Restore the prior
   clipboard for real.
3. **A real end-to-end loop driven by the hotkey** — press → record → transcribe → insert,
   with a menu-bar presence and clear state, not a manual click-through window.
4. **macOS permissions done properly** — `NSMicrophoneUsageDescription`, Accessibility
   handling, hardened-runtime entitlements, and a permission-recovery UX.
5. **Privacy that matches the docs** — local-only by default; if cloud is ever added it is
   opt-in, disclosed, and the docs say exactly what leaves the device. Temp audio is deleted
   after use.
6. **Correct, bounded audio** — handle all sample formats, cap duration, clean up files.
7. **Tests + CI** — cover config, state transitions, the transcription abstraction, missing
   model, failed transcription, insertion, clipboard restore, and the "no-network when
   local-only" invariant.

The new branch removes the DeepSeek implementation and rebuilds the core honestly. The
DeepSeek version remains on `main` for reference.
